# 算法手记

个人算法知识图谱与每日练习工作台。你可以记录实际用到的算法和案例，用关系图或筛选列表查看条目，并在同一个项目里练习、提交和打卡。

## 本地启动

需要 Node.js 24 或更新版本以及正在运行的 Docker。JavaScript、Python 和 Java 的评测运行时都在 Docker 镜像里。

```sh
npm run judge:build
npm start
```

打开 [http://127.0.0.1:4173](http://127.0.0.1:4173)。服务器没有 npm 依赖需要安装。只浏览知识库和题库时可以直接启动服务，运行代码前需要先构建评测镜像。

## 使用

- **知识图谱**支持算法、开发案例、练习题和代码实现四类条目。新建或编辑时可填写标签和关联条目。图谱视图展示中心条目及其邻居，详情中列出全部关联。列表支持按标题、正文、语言、类型和标签查找。
- **每日一题**使用首批 7 道原创题，默认按上海时间每天轮换。点击「运行示例」检查公开用例，点击「提交评测」运行公开和隐藏用例。当天题目用任一语言通过全部用例时记一次打卡。各语言提交和代码草稿分别保存。
- **评测报告**分别展示通过情况、实测最高耗时和峰值内存、时间与额外空间复杂度估算。耗时和内存包含语言运行时开销。复杂度通过本地代码规则估算，对常见循环、排序、集合和部分算法模式给出判断依据，识别不足时显示「待确认」。测试结果决定是否打卡。
- **数据**保存在 `data/algorithms.sqlite`。正式提交的代码和报告可在提交历史中查看。尚未提交的草稿保存在当前浏览器。

## 验证

```sh
npm test
npm run test:judge
```

集成测试需要可访问的 Docker 以及已经构建的评测镜像。测试使用临时数据库。

## 部署和扩展

可在带 Node.js 24 和 Docker 的主机运行。将数据库放在持久化目录里，并让具备身份验证的 HTTPS 反向代理访问服务的回环地址。代理须保留公开域名对应的 `Host`，并将该地址配置为 `APP_ORIGIN`。当前应用面向个人使用，代理负责访问控制。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 监听地址 |
| `PORT` | `4173` | HTTP 端口 |
| `APP_ORIGIN` | 空 | 反向代理的公开来源，例如 `https://notes.example` |
| `APP_TIME_ZONE` | `Asia/Shanghai` | 决定每日题和打卡日期 |
| `DATA_PATH` | `data/algorithms.sqlite` | SQLite 数据库路径 |
| `JUDGE_IMAGE` | `algorithm-notebook-judge:1` | 本机已构建的评测镜像名 |

评测容器以普通用户运行，网络关闭，根文件系统只读，无宿主机挂载，并限制 CPU、内存、进程数和运行时间。应用通过 Docker CLI 启动容器。

题目数据和轮换规则集中在 `src/problems.js`。以后接入外部题源时，可将数据转换为同一题目结构，再通过 `todayProblem(date, bank)` 传入有序题库。题目需要稳定 ID、示例、可用的隐藏用例和参考复杂度。当前评测约定输入为整数数组与可选的整数参数，输出为一个整数。接入使用其他输入输出约定的题源时，需要扩展评测适配器。
